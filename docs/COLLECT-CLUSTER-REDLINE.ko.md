# 지도에서 레드라인으로 전환할 때의 로그 수집

Windows PC에서 기존 차량 SSH 접속용 IP와 개인 키를 그대로 사용합니다.
개인 키 파일은 PC에서 SSH 인증에만 쓰고 수집 파일에는 넣지 않습니다.
차량에는 새 파일을 올리지 않습니다.

1. 차량에 평소 SSH로 접속할 때 사용하는 네트워크로 PC를 연결합니다.
2. 차량을 정차한 상태에서 Comfort와 순정 지도 화면을 준비합니다. 문제를 재현할 때의
   중심 표시 영역과 레드라인 표시 레이어 설정을 그대로 유지합니다.
3. `collect-cluster-redline.ps1`을 PC에 내려받고 해당 폴더에서 PowerShell을 엽니다.
4. 다음 명령의 IP와 키 경로만 본인 값으로 바꿔 실행합니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\collect-cluster-redline.ps1 -CarIp "192.168.차량.IP" -IdentityFile "C:\BMW\기존키경로\id_rsa"
```

`192.168.차량.IP`는 설명용 자리표시자입니다. 평소 SSH에 입력하는 실제 숫자 IP로 바꾸세요.
`ExecutionPolicy Bypass`는 이 PowerShell 프로세스에만 적용하며 시스템 정책을 변경하지 않습니다.

수집 안내가 나오면 **스포츠 모드로 한 번 전환**합니다. 약 55초 동안
깜빡이거나 선점되는 과정을 그대로 두고 완료될 때까지 기다립니다.
끝나면 실행한 폴더에 `cluster-redline-report-날짜-시간.txt`가 생깁니다.
그 TXT 파일을 보내면 됩니다. 키 파일은 보내지 마세요.

## 수집하는 내용

- 설치된 cluster-render 버전과 map/panel 관련 설정
- 3초 간격의 렌더러 상태 18회
- 설치된 레드라인 인스턴스들의 `cluster-redline-status.json` (1.2.49부터 레드라인은 상태 파일·로그를 남기지 않으므로 없음)
- 수집 전후 렌더러 로그 끝부분

설정·코딩·중심 표시 영역을 변경하거나 서비스를 재시작하지 않습니다.
슬롯을 선점하거나 해제하는 명령도 보내지 않습니다.

경로는 확인한 upstream 설치 구조의 기본값을 사용합니다. 펌웨어·설치 버전에 따라
파일이 없으면 `..._NOT_FOUND`를 기록합니다. 다른 경로로 설정돼 있다면 보고서의
`status_path` / `log_file` 값과 함께 다음 확인 방법을 정할 수 있습니다.

SSH 연결 오류가 나면 저장된 TXT에 오류가 남습니다. 기존에 쓰던 SSH 명령으로
접속이 되는지 먼저 확인합니다. 처음 접속하는 PC의 호스트 키 확인은 평소 SSH로 먼저 진행합니다.

## 원인 구분

레드라인 요청이 유지된 채 renderer가 `parked`와 `take-over`를 반복한다면
초기 슬롯 선점 경쟁을 살펴봅니다. 반면 앱 상태의 신호 유효 기간, 연결, 표시 요청이
계속 바뀐다면 앱이 화면을 해제·재요청하는 원인부터 구분합니다.
전송 실패나 fetch/map 오류는 각 로그를 함께 보아야 합니다.

현재 공개 upstream main의 cluster-render는 0.4.0입니다. 사용자 차량의 설치 버전은
보고서에서 별도로 확인합니다. 최신 소스의 재시도 간격을 구형 설치에 그대로 적용해
원인을 확정하지 않습니다.

도구의 원격 수집 부분은 테스트용 파일 구조와 누락 파일 사례에서 검사했습니다.
이 환경에는 Windows PowerShell과 차량 연결이 없어 Windows/실차 실행은 아직 확인하지 못했습니다.

HUD 미표시 문제는 [현재 레드라인 안내](CLUSTER-REDLINE.ko.md)를 참고하세요. 수집기에 HUD 설정도 포함됩니다.
